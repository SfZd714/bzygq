# 写项目经历的STAR和三段式法则

简历里的项目经历，是除了教育背景和实习经历之外**最重要的部分**。

面试官看简历的顺序大致是这样的：学历 → 实习单位 → 项目经历。项目经历往往是他们花时间最多、问得最深的一块。

写好项目经历是有方法的。这里分享两种：**STAR 法则**和**三段式法则**。

* * *

# STAR 法则

STAR 是一种叙述经历的结构框架，无论技术类还是非技术类项目都适用。

| 字母 | 含义 | 说明 |
| --- | --- | --- |
| S | Situation（情境） | 描述项目背景、时间、环境 |
| T | Task（任务） | 你在这个项目中具体承担什么任务 |
| A | Action（行动） | 你为完成任务采取了哪些具体步骤 |
| R | Result（结果） | 最终成果，尽量量化 |

## 示例

> **情境（S）**：在 xxxx 年，我作为 Java 开发团队成员，参与了公司订单管理系统的重构项目，目标是提升系统性能和可扩展性。
>
> **任务（T）**：负责设计和实现新的 RESTful API 接口，处理复杂订单查询逻辑，并与前端无缝集成。
>
> **行动（A）**：
>
> -   分析现有系统架构和性能瓶颈，与团队确定重构方案
>
> -   设计 RESTful API 端点，定义清晰的输入输出模型
>
> -   使用 Spring Boot + Hibernate + JPA 实现 API 开发
>
> -   编写单元测试和集成测试保障代码质量
>
> -   与前端紧密协作，输出 API 文档并通过代码审查推进协作
>
>
> **结果（R）**：
>
> -   按时交付，响应时间缩短 40%，超出预期
>
> -   代码可维护性显著提升，获得前端团队好评
>

**小技巧**：把每段项目经历套进这个模板梳理一遍，原本说不清楚的经历，往往会变得极其清晰。做项目时就可以提前按这个框架做记录，方便后期写简历。

# 三段式法则

STAR 法则信息量大，但结构稍复杂。如果面对的是**非技术背景的面试官**（国企里这类人不少），推荐用更简洁的三段式。

三段式和 STAR 本质相同，都完成了**发现问题 → 解决问题 → 取得成果**的闭环，但读起来更直白。

## 三段结构

**① 项目背景**

简洁说明项目来源和你的角色。重点突出能让项目"显分量"的背景信息：实验室背景、公司背景、行业规模等。

**② 工作内容**

描述你解决问题的过程，技术类经历要写清楚用到的具体技术点。

**③ 工作成果**

最重要的部分。整段经历的闭环，必须有产出——数据、交付物、效果，能量化尽量量化。

### 示例

> **项目背景**：xxxx 年，参与公司订单管理系统重构项目，负责设计和实现 RESTful API 接口，处理复杂订单查询逻辑，对接前端应用。
>
> **工作内容**：
>
> -   分析现有系统瓶颈，与团队制定重构方案
>
> -   设计 API 端点及输入输出模型，使用 Spring Boot + JPA 完成开发
>
> -   编写自动化测试用例，输出 API 文档，与前端团队协作完成联调
>
>
> **工作成果**：
>
> -   按时交付，接口响应时间缩短 40%
>
> -   代码可维护性提升，通过全部自动化测试
>

# 两种方法怎么选？

| 场景 | 推荐 |
| --- | --- |
| 技术岗位、年轻面试官、互联网背景公司 | STAR 法则 |
| 央国企、传统行业、年龄偏大的面试官 | 三段式法则 |
| 简历空间有限 | 三段式法则（更简洁） |
| 面试现场口头介绍 | STAR 法则（结构感更强） |

两种方法可以结合用：**简历上用三段式，面试现场口述用 STAR**，效果最好。
