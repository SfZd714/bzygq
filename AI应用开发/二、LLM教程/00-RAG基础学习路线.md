# RAG基础学习路线

这组文章面向准备央国企技术岗、国企科技子公司、运营商科技岗、金融科技岗、能源电力信息化岗，以及希望把 Java 后端项目升级到 AI 应用开发方向的同学。

RAG 不是一个单独的模型，也不是“把资料丢给大模型”，它本质上是一套检索增强生成架构：先从外部知识库里找到和问题相关的材料，再让大模型基于这些材料生成答案，学习 RAG 时，需要先建立几个基础判断：

1.  RAG 的核心不是“向量数据库”，而是“知识如何被处理、检索、组织并交给模型”。
    
2.  企业级 AI 应用里，RAG 比微调更常见，因为企业知识经常更新，且很多资料不适合写进模型参数。
    
3.  RAG 能降低幻觉，但不能自动消灭幻觉；检索错、切分错、材料冲突，模型仍然会答错。
    
4.  对后端同学来说，RAG 最应该按系统工程来准备：文档入库、向量检索、召回优化、Prompt 构建、权限审计、效果评估。

## 三、准备优先级

如果时间有限，可以按这个顺序准备：

| 优先级 | 内容 | 准备程度 |
| --- | --- | --- |
| P0 | RAG 基本原理 | 必须能画出“检索 + 生成”的完整链路 |
| P0 | 文档解析、Chunk、Embedding | 必须知道它们如何影响召回质量 |
| P0 | 向量数据库、Top-K 召回、相似度 | 必须能说明向量库在系统里的职责 |
| P1 | Query Rewrite、Hybrid Search、Rerank | 能结合“召回不准怎么办”回答 |
| P1 | Prompt 构建、引用来源、只基于材料回答 | 能说明如何降低幻觉 |
| P1 | 评估指标和人工验收 | 能说清命中率、答案正确性、引用准确性 |
| P2 | GraphRAG、Agentic RAG、多源 RAG | 了解趋势，不作为基础阶段重点 |

对大多数央国企技术岗来说，RAG 不需要你把所有论文细节背下来，但你必须能把工程闭环讲完整。尤其是“为什么召回不准”“为什么答案还是会幻觉”“怎么证明系统效果变好了”这类问题，面试官非常容易追问。

## 四、最后要准备到什么程度

比较理想的状态是：

```text
能解释 RAG 为什么不是单纯调用大模型
能画出离线建库和在线问答两条链路
能说明文档切分、向量化、向量检索和 Rerank 的作用
能分析 RAG 召回不准、答案幻觉、上下文超长的原因
能把 RAG 项目表达成一个完整后端系统，而不是停留在演示性实现
```
