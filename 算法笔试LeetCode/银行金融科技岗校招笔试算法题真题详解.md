## 一、30 秒结论

1. **考不考**：银行金融科技 / 信息科技岗笔试几乎必考编程题。形式多为线上机考，总行信息科技部、研发中心、信用卡中心及招银网络科技等科技子公司考察概率最高；编程题以 1~3 道为主，部分场次以「代码填空」形式出现，部分要求 ACM 模式手写。

2. **考多难**：整体明显低于互联网大厂，以 Easy~Medium 为主，极少出现 Hard。国有大行研发中心与招银网络科技会出中等难度题（连续自然数分解、合并区间、约瑟夫环、LRU）；信用卡中心与城商行相对更基础（字符串处理、数组操作、SQL）。

3. **题型结构**：主流是「行测 + 英语 + 专业知识 + 编程」四件套。编程题之外，银行最大的特色是 **SQL 大题** 与 **Python 数据分析题** 占比高，且 Java 是绝对主流语言。专业知识部分覆盖面广：计算机网络、操作系统、数据库、数据结构、Java/Spring、新兴技术（区块链、AI、云计算）都会涉及。

4. **怎么准备**：语言上准备 Java（最通用）+ Python（数据分析）+ SQL（必考）三件套。手撕保底题：字符串处理、数组双指针、链表反转、栈应用、二叉树层序遍历；模板题：摩尔投票、LRU、连续自然数分解公式、约瑟夫环递推、SQL GROUP BY 聚合与 HAVING 过滤。

### 4.1 统计字符串中字母与数字个数（招商银行信息科技岗 2025，Easy）

**题目描述**：给定一个字符串，分别统计其中字母与数字的个数并输出。

**输入格式**：单行字符串 s。

**输出格式**：两行，第一行字母个数，第二行数字个数。

**样例**

```
输入：AB12cd34
输出：4
4
```

说明：A、B、c、d 共 4 个字母，1、2、3、4 共 4 个数字；其余字符（如空格、标点）不计入。

**解题思路**：单次遍历，用语言内置的字符分类函数判断即可。Python 用 isalpha() / isdigit()；Java 用 Character.isLetter() / Character.isDigit()。

**参考代码（Python）**

```python
s = input().strip()
letters = sum(1 for ch in s if ch.isalpha())
digits = sum(1 for ch in s if ch.isdigit())
print(letters)
print(digits)
```

**参考代码（Java）**

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String s = sc.nextLine();
        int letters = 0, digits = 0;
        for (char c : s.toCharArray()) {
            if (Character.isLetter(c)) letters++;
            else if (Character.isDigit(c)) digits++;
        }
        System.out.println(letters);
        System.out.println(digits);
    }
}
```

**复杂度**：O(n)，空间 O(1)。

**易错点**：isalpha() 对中文字符也会返回 True，若题目限定英文字母需自行判断 ASCII 范围；用 else if 避免一个字符被重复计数。

### 4.5 连续自然数分解（工行 / 建行 / 农行金融科技岗，Medium）

**题目描述**：给定两个正整数 num 和 n，判断能否把 num 分解为 n 个连续自然数（首项 ≥ 1）相加的和。若能，返回按升序排列的这 n 个数；若不能，返回空列表。

**输入格式**：一行两个整数 num、n。

**输出格式**：能分解则输出升序排列的 n 个数（空格分隔）；否则输出空行。

**样例**

```
输入：18 4
输出：3 4 5 6
```

说明：3 + 4 + 5 + 6 = 18，且正好 4 个连续自然数。

**解题思路**：设首项为 x，则 n 个连续自然数之和为等差数列求和：

x + (x+1) + … + (x+n-1) = n·x + n·(n-1)/2 = num

1. num − n·(n−1)/2 必须能被 n 整除（否则 x 不是整数）；
2. x 必须 ≥ 1（自然数要求首项为正）。

### 4.11 LRU 缓存（招商银行信息科技岗，Medium）

**题目描述**：设计一个 LRU（最近最少使用）缓存，支持两个操作：get(key) 返回 key 对应的 value（不存在返回 -1）；put(key, value) 写入或更新，若缓存容量已满，淘汰最久未使用的 key。

**输入格式**：接口实现题，按指令调用 get / put。

**样例**

```
容量 = 2
put(1, 1)
put(2, 2)
get(1)     → 1
put(3, 3)  // 容量满，淘汰 key=2
get(2)     → -1
get(3)     → 3
```

**解题思路**：用「哈希表 + 双向链表」。哈希表让 get 达到 O(1)；双向链表按访问时间排序，越靠头表示最近使用。每次 get / put 命中后把节点移到头部；插入新节点放头部；容量满时删除尾部节点。Python 可用自建双向链表，也可用 OrderedDict；Java 可手写链表或直接用 LinkedHashMap。

**参考代码（Python，自建双向链表）**

```python
class Node:
    def __init__(self, key=0, val=0):
        self.key = key
        self.val = val
        self.prev = None
        self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.map = {}
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_to_head(self, node):
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key: int) -> int:
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node)
        self._add_to_head(node)
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.map:
            node = self.map[key]
            node.val = value
            self._remove(node)
            self._add_to_head(node)
        else:
            if len(self.map) == self.cap:
                last = self.tail.prev
                self._remove(last)
                del self.map[last.key]
            node = Node(key, value)
            self.map[key] = node
            self._add_to_head(node)
```

**复杂度**：get / put 均 O(1)。

**易错点**：双向链表删除时先改前驱再改后继，防止指针丢失；容量满时删除的是 tail.prev（最久未用），且要同步从哈希表删除；更新已有 key 时也要移动到头部。

### 4.12 线程安全计数器（平安银行信息科技岗 2025，Easy）

**题目描述**：实现一个线程安全的计数器类，提供 increment() 和 getCount() 两个方法，供多线程并发调用。

**输入格式**：接口实现题，不涉及输入输出。

**样例**：多线程各调用 increment() 若干次后，getCount() 返回所有线程累加的总数。

**解题思路**：直接使用 java.util.concurrent.atomic.AtomicInteger 即可保证原子性，代码最简洁且无锁、性能好。若不用原子类，可对 int 的读改写加 synchronized。核心是避免 i++ 这类「读-改-写」非原子操作在并发下的丢失更新。

**参考代码（Java）**

```java
import java.util.concurrent.atomic.AtomicInteger;

public class Counter {
    private final AtomicInteger count = new AtomicInteger(0);

    public void increment() {
        count.incrementAndGet();
    }

    public int getCount() {
        return count.get();
    }
}
```

**复杂度**：O(1)，无锁。

**易错点**：直接 count++ 不是线程安全的；getCount 也要通过原子方法读取；volatile 只保证可见性，不保证自增的原子性，不能替代 AtomicInteger。

### 4.13 SQL：每个客户的账户总金额（银行通用在线题，Easy）

**题目描述**：给定账户表 account，字段包括 account_id（账户号）、balance（余额）、customer_id（客户号）。每个客户可能有多个账户。查询每个客户的账户总金额，按总金额从高到低排序；总金额相同时按 customer_id 升序。

**建表与样例（简化）**

```
account:
account_id | balance | customer_id
    1      |  1000   |     1
    2      |  2000   |     1
    3      |  1500   |     2

期望输出：
customer_id | sum_balance
    1       |    3000
    2       |    1500
```

**解题思路**：GROUP BY customer_id 后对 balance 求和，再按总和降序、customer_id 升序排序。

**参考代码（SQL）**

```sql
SELECT customer_id, SUM(balance) AS sum_balance
FROM account
GROUP BY customer_id
ORDER BY sum_balance DESC, customer_id ASC;
```

**易错点**：SELECT 的非聚合列必须出现在 GROUP BY 中；金额相同时的次要排序条件别漏；聚合别名在 ORDER BY 中通常可用，但 WHERE 中不可用。

### 4.14 SQL：交易金额超过阈值的用户（银行通用题库，Easy）

**题目描述**：给定交易表，查询 2024 年每个用户的总交易金额，仅显示总金额超过 10 万元的用户，按总金额降序排列。

**建表与样例（简化）**

```
transaction:
user_id | amount | trade_date
   1    | 60000  | 2024-03-01
   1    | 50000  | 2024-05-01
   2    | 30000  | 2024-04-01
   2    | 20000  | 2024-06-01
   3    | 90000  | 2024-02-01

期望输出（阈值 100000）：
user_id | total
   1    | 110000
```

**解题思路**：先 WHERE 过滤年份，再 GROUP BY 聚合求和，HAVING 过滤总和超过阈值的用户，最后 ORDER BY 降序。注意 WHERE 与 HAVING 的分工：行级过滤用 WHERE，聚合后过滤用 HAVING。

**参考代码（SQL）**

```sql
SELECT user_id, SUM(amount) AS total
FROM transaction
WHERE trade_date BETWEEN '2024-01-01' AND '2024-12-31'
GROUP BY user_id
HAVING SUM(amount) > 100000
ORDER BY total DESC;
```

**易错点**：年份过滤不能放进 HAVING（amount 是聚合前的行级列）；HAVING 里建议直接写 SUM(amount) 以保证兼容性；金额阈值位数别写错。

2024-01-02 275.0
2024-01-01 150.5
```

**解题思路**：读取 CSV，按日期归组累加金额，最后按总额降序排序输出。可用标准库 csv + defaultdict，也可用 pandas。按金额降序排序即 O(n log n)。

**参考代码（Python，标准库）**

```python
import csv
from collections import defaultdict

daily = defaultdict(float)
with open("transactions.csv", encoding="utf-8") as f:
    reader = csv.DictReader(f)
    for row in reader:
        date = row["ts"][:10]          # 取日期部分
        daily[date] += float(row["amount"])

for date, total in sorted(daily.items(), key=lambda kv: kv[1], reverse=True):
    print(f"{date} {total}")
```

**参考代码（Python，pandas）**

```python
import pandas as pd

df = pd.read_csv("transactions.csv")
df["ts"] = pd.to_datetime(df["ts"])
df["date"] = df["ts"].dt.date
result = df.groupby("date")["amount"].sum().sort_values(ascending=False)
for date, total in result.items():
    print(f"{date} {total}")
```

**复杂度**：O(n log n)，排序主导。

**易错点**：时间戳格式不统一时先清洗；按日归组用 date 而不是原始时间戳；金额含千分位时先预处理；排序方向别搞反。

### 4.16 身份证号码校验（光大银行信息科技岗 2025，Easy~Medium）

**题目描述**：实现一个身份证号码校验函数。输入一个身份证号字符串，判断其格式是否合法。18 位身份证需满足：前 17 位为数字，第 18 位为数字或 X，且校验位正确；部分地区题还会要求判断归属地（如某市本地前 6 位为特定地区码）。函数需包含异常处理。

**输入格式**：单行一个身份证号。

**输出格式**：合法输出 VALID，否则输出 INVALID。

**样例**

```
输入：11010519491231002X
输出：VALID

输入：110105194912310021
输出：INVALID
```

**解题思路**：先做长度与字符格式检查（前 17 位全数字、末位数字或 X）；再按 GB 11643 校验位规则计算：前 17 位分别乘加权因子，求和后对 11 取余，余数对应的校验位字符与末位比对。异常处理用于捕获空串、类型错误等。

**参考代码（Python）**

```python
def check_id(id_str: str) -> bool:
    if not id_str or len(id_str) != 18:
        return False
    if not id_str[:17].isdigit() or not (id_str[17].isdigit() or id_str[17] == "X"):
        return False

    weights = [7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2]
    checks = "10X98765432"
    total = sum(int(id_str[i]) * weights[i] for i in range(17))
    return checks[total % 11] == id_str[17]

print("VALID" if check_id(input().strip()) else "INVALID")
```

**复杂度**：O(1)。

**易错点**：末位 X 必须大写（或先统一转大写）；加权因子顺序不能记错；「X」对应的余数是 2，不是 10；前 17 位必须全部是数字；严格校验还需验证出生日期与地区码，看题目要求。

## 五、难度对比与备考策略

### 5.1 银行 vs 运营商 vs 互联网

| 方向 | 代表题目 | 整体难度 | 特点 |
| --- | --- | --- | --- |
| 银行金融科技岗 | 连续自然数分解、合并区间、约瑟夫环、SQL 聚合、CSV 统计 | Easy~Medium | 业务场景多，SQL 与数据分析是特色，Java 为主 |
| 运营商（电信集团卷） | 判断两位数、RGB 交换、赛跑排名 | Easy | 编程题最友好，行测专业是分水岭 |
| 互联网大厂 | 图论、复杂 DP、困难数据结构 | Medium~Hard | 难度高，算法覆盖面广 |

### 5.2 备考优先级

1. **保底层（必须全对）**：字符串处理（统计、反转、IP 校验）、数组操作（移动零、最大子数组和、合并区间）、栈应用（括号 / 消消乐）、链表反转、二叉树层序遍历。这五类在招银、招行、光大、平安等场次反复出现。
2. **进阶层（拿稳 Medium）**：连续自然数分解（公式）、摩尔投票、约瑟夫环递推、LRU 手写、SQL GROUP BY + HAVING 聚合、Python 数据处理（csv / pandas 读取与分组汇总）。
3. **银行特色层**：SQL 大题（多表 JOIN、聚合、窗口函数 ROW_NUMBER）、数据分析题（pandas 清洗、统计、绘图）、Java 并发（AtomicInteger / synchronized）、Spring 框架基础知识。
4. **客观题层**：计算机网络、操作系统、数据库、数据结构、设计模式；招行系常考排序过程、栈队列、二叉树度与节点数。

### 5.3 应试技巧

- 银行编程题常给「代码填空」，读题时先确认空在哪个方法里、参数类型是什么，别改方法签名。
- 若要求 ACM 模式，注意输入可能有多行、多组用例，必要时写好循环读取。
- SQL 题先建表 / 确认字段名，再写 SELECT；聚合后过滤用 HAVING，别用 WHERE。
- 数据分析题先看有没有 pandas 环境；没有就退回标准库 csv + defaultdict，两种都要会。
- Java 岗多留意手写类：AtomicInteger、LinkedHashMap（可作 LRU 捷径）、StringBuilder。
